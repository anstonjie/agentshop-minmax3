一、问题 1：每集视频只有 10 秒

症状：7 集里 3 集 10 秒、其余 20~35 秒，与"每集 120 秒"的目标完全不符。
根因链（三段叠加）：
  • 上游 503 无重试：step4 i2v 遇 video_queue_full 直接记 failed（open-montage.service.ts:889-891），无退避重掷；11 镜并发打满上游队列，实测死亡率 90%。
  • 合成静默丢段：if(!sv.video_url) continue（open-montage.service.ts:1008），下载失败仅 warn（:1018），0 段才报错（:1023）；missing_shots 只上报不拦截（:1163-1164）——代码注释自证"成片短一截而用户完全不知道"。
  • 单段兜底 10s：i2v 时长 clamp(4,12)、缺省兜底 10（open-montage.service.ts:835，二次 clamp :1427）——存活 1 段时成片天然 ≈10s，与 DB 完全吻合。
排除项：集装箱目标（episode-boundary.ts:55,69 → novel-ledger.service.ts:451-453 → orchestrator:301,461）链路完好，产不出 10s 集；手动 onlyShot 补做路径无批次侧补做闸（orchestrator:404-408 只护批次路径）是次要入口。
修复：① step4 对 503/queue_full 加退避重掷（≤3 次，间隔递增）+ 每集 i2v 并发限速（对齐上游"每 key 每分钟创建限额"）；② step5 加成片门：composed/planned < 60% 或 durationSec < 45s 判不达标 → 不置 done，自动把 failed 镜写回 DramaBatch cursor 补做后重合成（复用现有断点续跑）；③ 补做仍不达标才 done，但 missing_shots 必须在剧集卡红字露出 + 一键补镜重合成入口（与问题 6 合并做）。
验收：重跑 1 集：durationSec ≥ 目标 60%、missing_shots=0 或有在跑补做任务；用 503 夹具（mock 上游全 503）证明门会拦、不会交 10s 片。

二、问题 2：小说与视频没有对齐

症状：小说→剧本→分镜→字幕→拉片，链路名字都在，但成片"不像这部小说"。
逐跳现状（v1 后复核）：
跳原文/逐字 quote 在不在证据
1 存储 → 2 beats 抽取 → 3 ledger 落库在（已自动化）novel-ledger.service.ts:230,362-421；beat-extract.ts:109-125（v1 P0-a 已落地）
4 剧本 → 5 分集大纲在episode-outline-prompt.ts:30-33,64-70 接 chapterExcerpt+beatsAnchor（v1 P0-b 已落地，实测锚点 3327 字真实正文）
6 分镜 shots断流大纲输出契约无 quote 字段（episode-outline-prompt.ts:122-140），beats 只活在提示词里没落 stepData → 分镜只拿 ≤50 字 scene.summary 重编（open-montage.service.ts:568-580；drama.service.ts:1371-1374）
7 字幕断流字幕=shot.dialogue（LLM 自造）+ASR（open-montage.service.ts:1096-1107；timeline.ts:229-231），与原著台词无对照
8 拉片/coverage 质检假通过check:coverage 仅手动端点（drama.controller.ts:575-589）；covered_by 全链路无回写（novel-ledger.service.ts:877 写死 pending）→ 真跑必全红但没人跑
另三处死代码/回退：arc.purpose 仍是章节标题 " / " 拼接（novel-pipeline.service.ts:117-129）；extractTaskUuid 要求 36 位 UUID 而 ledger key 是 64 位 sha256（novel-ledger.service.ts:107-110 vs :184）→ 小说圣经/logline 播种永不执行（:436-450）；重排后 episodes[].hook/cliffhanger 置空无回填（episode-boundary.ts:192-198）。
修复：① 大纲输出契约加 quotes[]（每场必引 1~3 条 beats quote 原文）并落 stepData → 分镜 shot.description/dialogue 强制引用（确定性门：dialogue 与 quote 的字符重合度阈值，不过门回炉）；② coverage 自动化：step5 后回写 covered_by，红项进剧集卡；③ 修 arc.purpose、extractTaskUuid 死分支、重排 hook 回填三处小修。
验收：抽 1 集人工对照：每镜台词/画面描述能指回原著 quote；coverage 自动报告红项清单可见；beats 表 status 不再恒 pending。

三、问题 3：字幕超屏 / 带说话人和表情

症状：字幕要么一行冲出屏幕，要么整行显示"人名：（表情）台词"。
根因（四个硬编码 + 一个设计开关）：
  • ASS 画布硬编码 PlayResX 512 / PlayResY 288（16:9）+ FontSize 12（timeline.ts:671/678），而成片默认 9:16 竖屏（open-montage.service.ts:350/762/1421）→ libass 按高度缩放，字被放大近一倍，18 字远超屏宽。
  • wrapCueText 固定 18 字/行，超限无上限并入末行（timeline.ts:541/563-567）→ 长台词末行爆宽。
  • 说话人前缀在折行之后追加、不占 18 字预算（timeline.ts:694/711；renderCueText:605-607）→ 首行 = 人名 + 18 字。
  • 安全区缺失：MarginL/R 仅 16/512（timeline.ts:678）；SRT 路径 force_style 无 Margin（open-montage.service.ts:1252-1260）；WrapStyle:2 关掉 libass 自动折行（timeline.ts:669）。
  • 说话人名是设计性回加：showSpeakerName 默认 'auto'、≥2 说话人即加前缀（timeline.ts:596-600），两处烧录调用都没传 false（open-montage.service.ts:1124/1126）。
  • 表情括注：09-15 的 dialogue-sanitizer 已能剥中文括号+全角冒号（dialogue-sanitizer.ts:57/79-83，dist 已含）；若仍见 = 无括号格式（"张三愤怒地你…"）未覆盖，或线上跑的是 09-15 前 build。
修复：① PlayRes/FontSize 按成片真实分辨率生成（竖屏 720×1280 档），maxChars 由像素宽推导；WrapStyle 改 0/1；② 取消"无限并入末行"，改增行或缩字；③ prefix+body 一起进折行预算；④ 烧录调用传 showSpeakerName:false（短剧字幕只要台词）；⑤ force_style 补 MarginL/R；⑥ sanitizer 补无括号"人名+表情副词"模式 + 击穿用例。
验收：竖屏成片截帧：任意 cue 不超安全区；字幕行无人名、无括注；用 30 字长台词夹具证明不爆宽。

四、问题 4：资产太少 + 多条胳膊坏图无检测无重生成

症状：资产数量少；人物定妆图出现多条胳膊（用户图 1/图 2）直接入库，无自动检测、无重生成。
根因：
  • 数量是提示词硬编码："主要角色 2-5、道具 2-6、场景按 scenes"（open-montage.service.ts:443），与小说实际人物数无关；且只建 character/location/prop 三组（drama.service.ts:863-864），vehicle/wardrobe 从不生成。
  • 零图像质检门：generatePortrait 只判"图是否下载落地" alive=!!local（drama.service.ts:970）；"多余肢体"只存在于负向提示词（video-prompt.ts:63）——坏图照判 ok 入库。
  • 重生成只兜硬失败且全手动：端点齐（POST assets/:id/portrait{force} ctl:252、/portrait-batch ctl:320、/variants ctl:364），UI 入口也有（卡片"定妆" tab:477、抽屉"整套重画" tab:977），但没有"坏内容→自动重生成"，也没有任何检测触发点。
修复：① 资产清单改由 ledger 实际抽取驱动（小说出现几个具名角色/场景/道具就建几个，上限放宽）；② 加视觉质检门quality_flag 入库；③ 资产卡露出检测结果 + "坏图重生成"按钮（复用 portrait force 端点）；④ vehicle/wardrobe 要么按小说抽取生成、要么从 chip 隐藏（与问题 5 合并）。
验收：用用户图 1/图 2 当夹具：质检门必须判不合格并触发重画；资产数 ≥ 小说具名角色数；坏图不再以 ok 状态入库。

五、问题 5：资产库"全部"有货、其他分类全空

症状：用户截图圈出 chip 行（全部/角色/场景/道具/载具/服装）：只有"全部"有内容。
根因（已亲自复核源码 + DB）：
  • chip 切换既不重新请求、也不客户端过滤：onTap 只 setState(() => _kind = ...)（drama_assets_tab.dart:435-439），GridView 原样渲染 _assets（:471-486）→ 分类视图显示什么完全取决于"上一次 _load 带的是哪个 kind"；任何带 kind 的刷新路径（搜索提交 :417、下拉刷新 :462、跑批结束刷新 :148）都会在你盯着某个 chip 时突然换列表——表现为分类内容错乱/空。
  • vehicle/wardrobe 恒空是真没数据：创建路径只写三组（drama.service.ts:863-864）；DB 实测 drama77：character 4 / location 4 / prop 3 / vehicle 0 / wardrobe 0。
  • 排除项：三侧 kind 取值一致（前端 chip tab:43-49 = 后端 where svc:1936 = 创建校验 svc:53,349），不是值不匹配；数据也在，不是后端查不到。
修复：① chip onTap 补 _load()（服务端过滤为准）+ 切换瞬间客户端先过滤防闪旧列表；② chip 加数量 badge（0 的类别灰显 + "本书未涉及"tooltip）；③ 与问题 4 ①合并：vehicle/wardrobe 按小说抽取生成，无则隐藏 chip。
验收：连点六个 chip，每类立即显示对应子集（drama77 应见 4/4/3）；空类别显示"本书未涉及"而非误导性的"暂无资产"。

六、问题 6：每集生成过程黑盒，不可看不可改

症状：每集用了哪些剧情段、参考图、提示词、字幕，没有集中展示；用户无法修改/替换/定位错步。
盘点结论：后端存得比前端展示的多得多。
  • 已落库：stepData 每步 {input,output,generatedAt,elapsed_ms}（drama.service.ts:1266-1271）；step2 分镜含 descWarnings/rhythmWarnings（open-montage.service.ts:628-634）；step3 关键帧含 prompt/ref_urls/ref_sources/degraded/error（drama.service.ts:1413-1450）；step4 含 i2v prompt/seed/status/error（open-montage.service.ts:880-891）；step5 含 missing_shots/audit/timeline_url（:1188-1216）；DramaBatch.log 全时间线；DramaAsset.refs[].prompt；beats quote。
  • 已展示：episode_step_views.dart 六步视图齐；但可编辑仅 step0 brief（:127-142）；重试只有整步重生成/单镜关键帧/单镜视频三种粒度。
  • 生了没存：本集所用 chapterExcerpt/beatsAnchor 进 prompt 即丢（drama.service.ts:1235-1238）；step0/step2 的 LLM prompt 原文丢（open-montage.service.ts:553-601）；字幕 cues 全文只落磁盘 timeline.json（:1114）。
  • 存了没展示：关键帧 prompt/ref 图、step4 i2v prompt/seed、warnings、missing_shots/audit、字幕内容（只显文件路径 :966-970）、资产 prompt、beats quote、Batch.log（工作台只取 log.last）。
  • 展示了不可改：后端 PUT steps/:step/output 已实现（drama.controller.ts:433-439）但前端零调用；POST keyframe/preview（ctl:266-274）零调用；字幕改后无重烧端点；缺镜无"补这几镜再合成"入口。
修复：① 回填三样进 stepData：quote 锚点、prompt_used、字幕 cues；② episode_step_views 每步加"提示词/证据"折叠块（关键帧缩略图+ref 来源、i2v prompt/seed、warnings、missing_shots/audit、字幕预览）；③ 接上 PUT output：分镜台词/描述行内编辑→单镜重出；关键帧可换参考图重出；④ 新增字幕重烧端点 + 缺镜一键补合成；⑤ 工作台加 Batch.log 全时间线页（哪步错、错因、扣分一目了然）。
验收：任选 1 集：能看到本集 quote 锚点/每镜 prompt/字幕全文；改一句台词不重跑整步即可重烧；missing_shots 有一键补做按钮。

七、问题 7（最严重）：集与集之间没钩子、断断续续

症状：完整小说做出来的视频集间断裂、无悬念承接。
机制盘点：文本层已通，画面层全没通电。
连贯性机制状态证据
beats→大纲锚点 / 分集边界落钩子章尾 / hookOut→下集 hookIn（文本）已实现beat-extract.ts:29,109；novel-anchor.ts:91-124；episode-boundary.ts:113,151；drama.service.ts:1317-1320
角色/场景资产跨集复用（防换脸）已实现keyframe-plan.ts:132-209；seed 锁定 drama.service.ts:1404

上集尾帧→下集首帧 / 镜头间尾帧接力默认关relay 仅集内链且 flag off（relay-plan.ts:8-9；open-montage.service.ts:901-902，DRAMA_SHOT_RELAY）
转场（叠化/match-cut 替代裸 concat）默认关transition-plan.ts:7；open-montage.service.ts:1052-1055（DRAMA_COMPOSE_TRANSITIONS）

死镜/接缝硬跳质检只测不拦video-audit.ts:357；open-montage.service.ts:1166-1185（verdict 仅 review，不回炉）
放大器：问题 1 让每集只活 1~3 镜——叙事节拍整段丢失，hookIn/hookOut 写得再好也没有镜头去演它。"断断续续"= 生存层（问题 1）+ 画面承接层（本表）双重叠加。
修复：① 先修问题 1（镜活下来，钩子才有载体）；② relay 尾帧接力 + 转场 flag 默认开（配 i2v 限速，成本 ≈ 最长链长 × 63s/集，v1 已实测）；③ rhythm-guard 加"集尾钩子镜头"硬约束：末镜 rhythm 必须 ∈ {turn, cliffhanger, payoff}，不过门回炉重排（warn→block）；④ openHooks 回写接通；⑤ 集首 3 秒视觉回顾（上集尾帧淡入 + 一行回顾字幕）替代被禁的旁白回顾，需用户拍板；⑥ video-audit 死镜/硬跳从 review 升级为回炉触发（与问题 1 补做通道共用）。
验收：相邻两集：下集首帧与上集尾帧同源（relay 链命中）；每集末镜 rhythm 命中钩子角色；video-audit 接缝跳变数前后对比下降；人工连看 3 集能复述"上集留了什么悬念、本集怎么接的"。

十、风险与前置
